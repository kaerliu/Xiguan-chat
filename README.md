# 吸管 AI 接待交互原型

这是一个前端单页原型，覆盖：

- AI 接待创建、配置、调试与发布
- 会话查看、人工接管与回复
- 访客线索和 Q&A 洞察
- 企业切换、成员、套餐与个人设置

## 运行

安装 Node.js 后，在项目目录运行（无需安装第三方依赖）：

```bash
npm run dev
```

然后访问 `http://127.0.0.1:8123`。

请使用该本地服务编辑「产品逻辑」。保存会直接更新仓库中的 `product-logic.md`，因此可以随其他代码一起提交。在线部署只读取该文件并以只读方式展示，不会把修改保存在访客浏览器中。

「主动获客 · 形象引导」读真实官网也要靠这个本地服务：`dev-server.js` 的 `/api/page-snapshot?url=…` 去抓网页，去掉脚本、补上资源基准地址后返回。在线部署（静态托管）没有这个接口，形象引导会退回示例官网。靠脚本渲染内容的页面（去掉脚本后是空的）读不出区块。

首次打开会显示官网入口。输入官网后先模拟扫码授权，再进入工作台解析；直接注册则在工作台输入官网。已创建助手的回访用户直接进入工作台。

## 智能体搭建页的文件分工

「角色与提示词 / 能力 / 主动获客 / 知识库 / 外观」五页按控制台源码还原，另有新增的「通知推送」页，代码拆在这几个文件里（`index.html` 按下面的顺序加载）：

- `agent-capabilities.js`：能力列表与每个能力的配置详情、右侧演示（留资、转人工、资料交付、主动弹窗、沉默跟进，以及测评式营销、留资弹窗、推荐消息、MCP 调用）。
- `agent-toolbar.js`：官网侧边工具栏的模板、按钮编辑器、弹出面板预览和图片上传处理。
- `agent-appearance.js`：外观页。外观模板、官网入口（数字人 / 悬浮入口 / 中间按键，可同时开启多个；留资弹窗开启时指定主入口）、每个入口的大小和位置（预览里拖动或用滑块）、手机端入口（继承悬浮入口样式，只调位置）、对话窗口（可模拟人工接入）、快捷按钮、显示设置，以及本页的保存、放弃和离开提示。桌面端预览用 iframe 显示官网，地址默认取 onboarding 填的官网。
- `agent-acquisition.js`：「主动获客」页。把按页面规则触发的几项（形象引导、留资弹窗、主动弹窗、沉默跟进）从「能力」里单独拿出来列在这里；形象引导的规则配置（出现条件、站在哪、形象动作、话术、按钮调用哪个能力、打扰控制）也在这个文件。最上面填官网页面的网址，读完页面会按识别出的区块生成规则建议（原型里话术按区块标题套模板，没有接模型）。站位有两种并存：每个区块四个预设点位，或在右侧预览里拖小吸定手动位置，两种存的都是相对区块的位置，后三项的详情页仍在 `agent-capabilities.js`。
- `mascot-preview.html`：形象引导右侧的效果预览，嵌在 iframe 里，规则用 postMessage 传入；单独打开时用内置的示例规则自己播。填了网址时，它向本地服务要页面快照，放进同源的 iframe，在真实页面上识别区块、算四个点位（会避开挡住文字和图片的位置）、演示和拖动；没填或读不到时用自带的示例官网。形象的动法是静态姿势图加代码（换图、整体摆动、手臂绕肩转、眨眼和视线、待机转头），素材在 `assets/mascot/`。
- `assets/mascot/`：小吸的 16 张姿势图（含跳跃的腾空、落地两张和朝左指的一张）、8 张转头用的头部角度图、3 张小心心，以及外观页用的立绘 `xiaoxi-figure.webp`。
- `agent-config.js`：草稿状态（保存 / 放弃 / 发布窗口）、角色与提示词、对话窗口本体，以及上面几个文件的事件接入。
- `agent-knowledge.js`：知识库页。
- `agent-notifications.js`：「通知推送」页。首页是通知目标卡片、推送记录和推送规则；企业微信群机器人（多个群、按事件订阅、测试发送、消息预览）和简道云表单（读取应用和表单、字段映射、写入预览）两个详情页。这里的配置保存即生效，不走草稿和发布，单独存在浏览器本地（`xiguan-agent-notify`）。简道云的应用、表单、字段和企业微信的测试结果都是原型里的示例数据。需求见 `PRD-渠道与通知推送-v1.0.md`。
- `product-logic.html`：产品逻辑记录页；本地环境可编辑，线上环境自动只读。
- `product-logic.md`：产品逻辑的唯一内容源，随代码提交和部署。
- `dev-server.js`：零依赖本地服务，静态托管原型并将产品逻辑保存回仓库文件。
- `assets/xiguan-logo-fill.png`：对话窗口底部「吸管 提供技术支持」的图标。

概览与五个配置页共用同一套顶部草稿状态和发布操作；角色、能力、知识库与外观配置保存在浏览器本地（`xiguan-agent-config-draft` / `xiguan-agent-config-published`），渠道与通知推送配置保存即生效，分别独立保存在 `xiguan-agent-channels` 和 `xiguan-agent-notify`，清空对应键即可恢复默认。


## 2026-11-18 高保真 onboarding

界面基线为 [Xiguan-chat](https://kaerliu.github.io/Xiguan-chat/) 对应仓库 `ed77fdf`。`app.js`、`styles.css`、`agent-config.js`、`agent-appearance.js`、`agent-capabilities.js`、`agent-toolbar.js`、`agent-knowledge.js` 直接复用该版本源码，工作台及对话组件不再被 onboarding 样式重新设计。

- [高保真工作台预览](http://127.0.0.1:8123/index.html?flow=preview)：直接查看接好 onboarding 的完整概览与调试台；没有已有配置时使用内存中的帆软示例，不覆盖保存的助手。
- [产品界面](http://127.0.0.1:8123/index.html)：已配置助手的用户直接进入工作台。
- [输入官网流程](http://127.0.0.1:8123/index.html?flow=new)：输入官网 → 扫码体验登录 → 原版工作台解析 → 官网与助手预览。
- [直接注册后的流程](http://127.0.0.1:8123/index.html?flow=direct)：在原版工作台输入官网，自动解析并生成默认配置。
- [场景切换](http://127.0.0.1:8123/onboarding-review.html)：外部评审工具，可检查解析失败、主题色回退与官网无法预览。该工具条不属于产品界面。

概览保留原版的配置、运行轨迹和提示词 / 知识库 / 能力 / 外观分类；仅在首次完成时增加可关闭的就绪提示和大尺寸开始试用按钮，点击切换到对话窗口。调试台直接使用原版官网浏览器、对话窗口、输入区、消息和快捷按钮，在原预留操作位增加分享和放大。各配置页、保存草稿和发布弹窗均复用原实现。

`onboarding.js` 只接入首次路径、扫码承接、解析状态、就绪反馈、只读分享和转场。解析弹窗先收拢到调试台的网址框，落位后填入网址，再露出提前加载的官网。真实官网 iframe 不移除、不重建；移动的是弹窗本身。官网右下角对话窗口默认收起，点击入口后才展开。输入官网弹窗不展示抓取范围和页数说明。`onboarding.css` 仅定义 onboarding 自身样式和新增状态，不覆盖原版工作台与访客组件。上一版入口文件保存在 `versions/onboarding-v4/`。

原型边界：扫码通过体验登录按钮模拟成功；二维码是示意图。官网 iframe 为真实地址；官网解析、最多 5 页数据、主题色和问答仍用本地示例。任意未知域名会说明尚未接入真实解析服务，不假装识别其业务。分享将名称、颜色、欢迎语和业务摘要写入 URL 快照，分享页没有配置入口；本地链接仅当前设备可访问。部署保留在原渠道页。

验证：语法检查与 `git diff --check`；原始组件文件与来源逐文件比对；Chrome 检查原版配置分类、运行轨迹、对话试问、官网预览、分享、官网输入弹窗及解析自动承接。生产授权、官网抓取、检索问答和服务端分享权限仍是后端接入范围。

本轮仅收敛新增 onboarding：就绪区使用白底细边框，去掉勾选图标与绿色整块背景；标题改为官网资料已导入，保留 40px 高开始试用按钮；弹窗落到网址框的转场缩短为 420ms，官网以 160ms 淡入，不再闪色。右下角对话默认收起，输入官网不展示抓取范围说明。
